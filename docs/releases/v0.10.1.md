to the thing v0.10.0 introduced, found twenty minutes after publishing it
by running the real download against the real release.

---

## Update downloaded the WordPress plugin instead of the app

v0.10.0 gave a downloaded install the ability to update itself. That
updater asked GitHub for the latest release and took the first attached
file whose name ends in `.zip`.

A release has two: the app, and the WordPress bridge plugin. The plugin
is 30 KB and it sorts first.

So pressing **Update** on v0.10.0 downloads the plugin, cannot find the
app inside it, and stops:

```
Downloading seo-tool-bridge.zip…
Downloaded 0.0 MB
Unpacking…

The downloaded archive does not look like this app — no
package.json inside it. Nothing has been changed.
```

It refuses rather than doing damage — the archive is validated before
anything is overwritten, which is why this cost a confusing message
instead of someone's install being replaced by a WordPress plugin. But
on v0.10.0 the Update button does not work.

**If you are on v0.10.0, download this release manually once.** From
v0.10.1 onward the button works, verified end to end against this
release.

The filename now has a single owner: the script that writes
`seo-tool-v<version>.zip` and the updater that looks for it call the same
function, because the two disagreeing about the name is exactly what
this was.

## Download refreshed 30 Oct 2026, 16:25 UTC

`seo-tool-v0.10.1.zip` was rebuilt from `main` after this release was
first published, so it now also contains:

- **The dot legend, profile block and guided/pro toggle moved out of the
  sidebar and into the top bar.** Two of the three were already in the
  top bar, so the sidebar was carrying a second copy of them with
  different wording for the same switch. The foot of the sidebar is now
  just the "Local · everything on this machine" line.
- **README top navigation now reads as buttons** rather than a row of
  blue links.

**The version number is unchanged, deliberately and with a cost:** an
install already on v0.10.1 will press **Update** and be told it is
already up to date, because the updater compares version strings. If you
want these changes on an existing install, download the zip from this
page and unpack it over your copy — your database, `.env.local` and
backups are untouched by that, the same files the updater itself
preserves.

The `v0.10.1` **tag** still points at the commit this release was cut
from. The zip is newer than the tag; `main` is the source of truth for
what is in it.
