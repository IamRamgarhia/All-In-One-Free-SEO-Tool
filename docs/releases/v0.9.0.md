## ⚖️ The app was telling you the wrong licence

**Read this if you ever looked at the About page and decided what you could
do with this software.**

That page carried a panel headed *"License — free to use, not free to sell"*.
It said the project was published under a **noncommercial** licence, linked
to that licence's text, and listed, in a red column, things you supposedly
could not do without written permission: sell the software, offer it as a
paid hosted service, re-license it, or strip the credit and rebrand it.

**All four of those are allowed.** This project has been
[MIT](https://opensource.org/license/mit) since June 2026. The `LICENSE`
file, the `package.json` and the README badge have all said MIT the whole
time; only that page disagreed, and nothing in the build noticed, because
`LICENSE` and the page had no connection to each other.

So: you can sell it, host it as a paid service, fork it commercially, and
remove the maintainer credit. MIT asks two things in return — keep the
copyright notice in copies of the source, and accept that there is no
warranty. There is no commercial licence to buy, and the page no longer
offers one.

`license-claims.test.ts` now reads `LICENSE` and fails the build if any
user-facing file names a different licence, or offers a commercial licence
that does not exist. A licence is the one piece of text in an app that must
never be out of date.

The same page also claimed "100+ tools" in one paragraph and "150+ tools" in
another, while the README said 92. Both are gone rather than replaced with a
third number.

## 🤖 Claude Code works your tasks in the client's folder

Thanks to [@Galbir](https://github.com/Galbir) ([#49](https://github.com/IamRamgarhia/All-In-One-Free-SEO-Tool/pull/49)).

Point a client at a local project folder and the app can hand its tasks to
Claude Code running on your own machine:

- **A chat per task**, with a model and effort picker, that works in the
  client's folder and streams what it is doing.
- **A pull request per queue run** — branch, commit, push, open, and a
  task list with Merge and Merge all.
- **Per-client autopilot**, so the daily agent's findings get worked rather
  than just listed.
- **Five new MCP tools** — `list_tasks`, `get_task`, `update_task`,
  `list_publish_queue`, `get_queue_item` — so an assistant can read your task
  list and the review queue directly. 28 MCP tools now.
- Documents that are not part of the site stay out of the client's repo.

### It is off until you switch it on

This is the part to read before updating. Everything that runs a program on
the machine hosting the app — `claude`, `gh`, `git`, the folder picker — is
**off by default**. Turn it on in **Settings → Claude Code on this computer**,
or with `SEO_TOOL_HOST_AGENT=1`.

While it is off, those routes answer `403`, nothing is spawned, the autopilot
skips clients it would have worked, and the dock is not drawn.

**`SEO_TOOL_HOST_AGENT=0` is a hard off that the Settings page cannot undo.**
Put it in the `.env` or Dockerfile of any install other people can reach. This
install can run behind a single optional password, and without that line an
exposed one would hand a signed-in visitor a coding agent on the host.

Verified on a running build rather than taken on trust: with the setting on
*and* `SEO_TOOL_HOST_AGENT=0`, every one of those routes still refuses, and
the Settings page says "Forced off by `SEO_TOOL_HOST_AGENT=0`" instead of
showing a switch that would do nothing.

**Four database migrations** come with this (0071–0074). Back up before
updating — the launcher's Back up button, or `/api/backup`.

## ❤️ Support & about

The About page is now **Support & about**, and it is in the sidebar instead of
being reachable only from the profile menu.

- **A live supporters tracker** — what has come in, from how many people, a
  goal with a progress bar, and the names to thank with a search once the
  list outgrows a glance. The figures live in `supporters.json` at the root of
  the repo, so they update everywhere without a release.
- **The figures work offline.** The last usable set is cached in your own
  database, and the panel tells you when it is showing a cached figure rather
  than a fresh one.
- **Help without paying comes first on the page**, before any mention of
  money: star it, send it to another SEO, report a bug. Those genuinely
  matter more.
- **A dashboard card**, after five audits and at most once a day. "Not today",
  "Hide for 30 days" and "Never ask again" each do exactly what they say.

**It never appears on anything your clients see.** Not the client portal, not
a PDF report, not an invoice. You send those to people who pay you, and the
maintainer's tip jar is not your business.
`support-surfaces.test.ts` fails the build if that ever slips — if a
client-facing file imports the support components, if the card is mounted
anywhere but the dashboard, or if it reaches a layout.

Writing the tests for the tracker found a bug worth the trouble:
`Number(null)` is `0` in JavaScript, so a `supporters.json` missing its total
would have rendered a confident **"₹0 received so far"** that nobody had
written. Absent and zero now give different answers, and a file that cannot
be read shows no panel rather than an invented one.

## Upgrading

**Four migrations** (0071–0074). **Back up first.** The WordPress plugin is
unchanged at **0.6.1**, and there are no new dependencies.

- **Desktop launcher:** open it and press **Update**.
- **Installer:** re-run the same one-liner from the README.
- **Docker:** `docker compose up -d --build`.
- **Git:** `git pull && pnpm install && pnpm build`.

If your install is reachable by anyone else, add `SEO_TOOL_HOST_AGENT=0` to
its environment while you decide whether you want the Claude Code features at
all.
