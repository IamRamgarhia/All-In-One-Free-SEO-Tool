# v0.6.0 — All-In-One Free SEO Tool

**Release date:** 2026-09-23
**Diff:** [v0.5.1 → v0.6.0](https://github.com/IamRamgarhia/All-In-One-Free-SEO-Tool/compare/v0.5.1...v0.6.0)

Most of this release fixes places where the tool gave you a confident
answer that was wrong. Nothing crashed, nothing was logged, and the
number looked exactly like a real one — which is why several of these
survived for months.

The rest of it is the agent doing more of the work: it can now apply
fixes for **29 of the crawler's 72 finding types**, up from 7.

## Numbers that were wrong, now fixed

If you have been using this tool, these changed what you see. Each one
was measured, not guessed.

- **A blocked search read as "not ranking."** DuckDuckGo answers
  suspected bots with a puzzle page over HTTP 202, which the code
  accepted as success and parsed as zero results. So rank checks wrote
  "not ranking" into your history, competitor discovery found nobody, and
  directory checks said "not listed." Search pages are now classified —
  blocked, genuinely empty, or unreadable — and a failed check is no
  longer stored as a position. **If your rank history has flat
  "not ranking" stretches, that is what they were.**
- **The algorithm update list was invented.** It contained a "September
  2025 core update" that never happened, dated the December 2025 one a
  week early, and had nothing from 2026. It now comes from Google's own
  Search Status Dashboard — 41 incidents with Google's announcements,
  refreshed daily.
- **WordPress sites with clean URLs were told to fix their permalinks,**
  at high severity, because the check matched the `?p=123` shortlink
  WordPress puts in every page's head.
- **The malware scanner called a stock WordPress file a critical
  breach.**
- **The crawler reported Cloudflare's own plumbing as broken pages.**
- **Quick wins included low-severity findings** while calling them high
  impact.
- **The page monitor ignored a page going 404 or 500** and never read
  noindex. It now records status, robots directives and structured data,
  and rates each change critical / warning / info.
- **GEO citability scored scripts and JSON-LD as if they were prose.**
  Measured before the fix: 4 of 10 scored passages on one Google doc were
  script and structured data.
- **Core Web Vitals could crash the page.** Google sends CLS as a string;
  the code formatted it as a number. A missing percentile became 0, which
  rates as "good."
- **The dashboard called an AI model on every page load.** If you pay per
  token, this was costing you money for nothing.
- **Keyword discovery read your meta description as word soup.** It now
  reads the site.

## The agent fixes more of what the crawler finds

**7 → 29 of 72 finding types**, with a test holding that as a floor so it
cannot quietly regress.

New things it can apply and undo: canonical tags, robots directives,
Open Graph and Twitter tags, alt text, redirects, internal links, schema,
site hardening, and the first site-wide fix — your robots.txt AI crawler
policy.

- **It works on any site behind Cloudflare now**, not only WordPress.
- **Approve a whole class of change at once** instead of one at a time.
- **A page the agent cannot edit is reported as a skip, not a failure.**
- Your autonomy setting still decides everything. The default is still
  **suggest** — nothing is written to a live site until you say so.

⚠️ **Three WordPress plugin bugs were writing changes that never
appeared on your site:** alt text was saved to the database and never
rendered, the meta description and canonical were never printed, and Open
Graph could be written but never taken back. **Update the plugin** (see
upgrade notes).

## Task lists check your site before making work

New clients used to get a fixed checklist per platform and niche, written
without looking at the site. On a real install, **8 of 13 open tasks were
advice about work finished years ago** — add canonical tags (every page
had them), generate a sitemap (it was already in robots.txt), enable
HTTP/2 (it was already on).

The tool now reads your site first — homepage, a few internal pages,
robots.txt, sitemap.xml, cache headers, the TLS handshake — and skips the
tasks you have already done, writing the evidence to your activity log so
you can check it.

**If it cannot tell, it keeps the task.** An unreachable site produces
exactly the old checklist.

## Connect Claude (or any MCP client) to your own data

- **22 tools** over stdio and, new in this release, a **remote HTTP
  endpoint** so chat connectors can attach. It is off until you generate
  a token in Settings → AI connection.
- **A read-only token** that reaches 15 of the 22 tools and cannot run the
  agent or edit your site. This is the one to paste into a chat app.
- **A request cap** of 120 a minute per token.
- Per-client setup with the commands already filled in, and **Claude
  Desktop on Windows works now** — `npx` in the config never did.
- Search Console over MCP: inspect a URL, check indexing, compare two
  periods, list sitemaps. Read-only, and periods end on the last day
  Google has finished counting so a part-counted day cannot look like a
  traffic drop.

## Google, AI providers, and install

- **Connect Google with a service account** — no consent screen, no
  browser, and no connection that silently dies after a week (the old
  setup guide built exactly that).
- **Claimed crawlers are verified against their owners' published IP

- **Connect an AI subscription instead of an API key**, and see what each
  tool costs before you run it. **Every AI tool runs now — it was 7 of
  19.** Gemini was spending its whole output budget on thinking and every
  tool blamed itself for the empty result.
- **The Windows download-and-double-click path never worked.** It does
  now.

## Security

- **Eleven tools would fetch whatever host you typed**, including
  addresses on your own network. All of them now go through the same
  guard, on every redirect hop.
- Three CMS writers accepted a revision id and threw it away, which meant
  undo silently did nothing.

## Tested

Everything in this release was run, not assumed:

- 1,056 unit tests across 88 files; typecheck and lint clean; production
  build
- Crawler fixture coverage went from 20 to 62 checks — built against a
  site made to be broken, which found several crawler bugs
- End-to-end tests now assert what a page *says*, not that it exists

  silently skipping for weeks, and running them found two more bugs.
- MCP: 47 checks over stdio, 11 over HTTP against the built app

a paid index, rank checks from one machine are one sample from one
location, and AI features need either a local model or your own key.

## ⚠️ Upgrade notes

### Database

**Nine migrations apply automatically on next start** (0062–0070). No
action needed and no downtime.

### WordPress plugin — please update

The plugin goes **0.4.0 → 0.6.1**. Three fixes in it change whether your
edits reach your live site at all (alt text, meta description, canonical),
so an old plugin will keep silently dropping them. The app tells you when
a capability needs a newer plugin rather than failing quietly.

### Nothing else

No config changes, no new required keys. The tool still works with no API
keys at all.
